# Workspace Context Index

## Overview
This document serves as the index and guide for AI models to understand and work with the **asdm-core-assets-mcp** workspace. It provides a structured overview of the workspace content and guides AI models to find relevant context.

## Workspace Information

### Basic Information
- **Workspace Name**: asdm-core-assets-mcp
- **Description**: Central asset repository for the ASDM (AI-First System Development Methodology) platform, providing toolsets, skills, specs, MCPs, and contexts for AI-assisted software development
- **Created Date**: 2025
- **Last Updated**: 2026-05-09

### Technology Stack
- **Primary Languages**: TypeScript, Markdown, JSON, Shell (Bash), Python, JavaScript (Node.js)
- **Frameworks Referenced in Skills/Specs**: Spring Boot 3.x, FastAPI, Gin, ASP.NET Core, React 18, Vue 3, Next.js
- **Build Tools**: npm, tsc (TypeScript compiler)
- **Runtime**: Node.js >= 18
- **Testing Framework**: Jest (codebuddy-log-parser)
- **CI/CD Platform**: GitHub Actions
- **AI Engine**: Tencent CodeBuddy (`@tencent-ai/codebuddy-code`)

### Business Context
- **Business Domain**: AI-assisted software development methodology (ASDM)
- **Key Business Processes**:
  - Asset distribution: Toolsets, Skills, Specs, MCPs, and Contexts are synced from this repo to the ASDM Platform
  - Context injection: Workspace context files are injected into AI coding assistant sessions
  - Skill-based code generation: PRD Builder delegates code generation to Skills based on detected tech stack
  - Prototype generation: Rapid frontend prototyping with mandatory spec reading
- **Business Rules**:
  - All content must be in English for internationalization
  - Each asset type has a central JSON registry tracking metadata and versions
  - Toolsets detect the Agentic Engine provider (CodeBuddy, Claude Code, GitHub Copilot) and install commands accordingly
  - Skills generate code following specific stack conventions defined in Specs

### Key Directories Explanation
- **`.asdm/contexts/`**: Generated context files for AI model reference — this is where context-builder output goes
- **`asdm-core-assets/`**: The primary asset library — all toolsets, skills, specs, MCPs, and contexts are defined here
- **`asdm-core-assets/skills/`**: Code generators that produce CRUD layers, DDL, PDFs, PPTXs — each has scripts and SKILL.md instructions
- **`asdm-core-assets/specs/`**: Markdown coding standards injected as AI context for specific tech stacks
- **`asdm-core-assets/toolsets/`**: Bundles of actions + specs that perform structured AI workflows
- **`asdm-core-assets/mcps/`**: Model Context Protocol server configurations for external tool integration
- **`tools/codebuddy-log-parser/`**: Internal utility for parsing CodeBuddy session JSONL logs
- **`.codebuddy/commands/`**: Slash commands installed for the CodeBuddy AI coding assistant
- **`.github/workflows/`**: CI/CD pipelines for packaging, workspace execution, and context sync

## Development Guidelines

### Building and Compilation
```bash
# Build codebuddy-log-parser
cd tools/codebuddy-log-parser
npm install
npm run build

# Run the CLI tool
node dist/index.js --input log.txt --output parsed-output.json
```

```bash
# Run tests for codebuddy-log-parser
cd tools/codebuddy-log-parser
npm test
```

- **Formatting**: EditorConfig with 2-space indent (4-space for Java/Python)
- **Language Rule**: All code, documentation, comments, variable names, file names must be in English

## AI Model Guidance

### How to Use This Context
1. **Start with this index** to understand the workspace structure
2. **Refer to specific context files** based on the task at hand
3. **Follow the development guidelines** for building, testing, and deployment
4. **Maintain consistency** with existing patterns and conventions

### Common Tasks
- **Adding a new skill**: Create directory under `asdm-core-assets/skills/` with `SKILL.md`, scripts, and register in `skills-registry.json`
- **Adding a new spec**: Create directory under `asdm-core-assets/specs/` with spec markdown files and register in `specs-registry.json`
- **Adding a new toolset**: Create directory under `asdm-core-assets/toolsets/` with `INSTALL.md`, `README.md`, `actions/`, and register in `toolsets-registry.json`
- **Adding a new MCP**: Create directory under `asdm-core-assets/mcps/` with `config.json` and register in `mcps-registry.json`
- **Modifying CI/CD**: Edit workflow files in `.github/workflows/`
- **Updating CodeBuddy commands**: Edit files in `.codebuddy/commands/`

### Asset Registry Pattern
All assets follow a common registry schema:
```json
{
  "version": "1.0.x",
  "dateCreated": "ISO8601",
  "dateUpdated": "ISO8601",
  "<asset-type>": [
    {
      "id": "string",
      "guid": "UUID",
      "name": "string",
      "description": "string",
      "version": "semver",
      "downloadUrl": "string",
      "path": "string",
      "entryPoint": "string",
      "dateCreated": "ISO8601",
      "dateUpdated": "ISO8601"
    }
  ]
}
```

### Troubleshooting
- If context-builder commands are not available, check `.codebuddy/commands/` for slash command files
- If CI/CD packaging fails, verify registry JSON files are valid and asset directories exist
- For CodeBuddy execution issues, check `tools/codebuddy-log-parser/` output
